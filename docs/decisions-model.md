# Model stream decisions

Decisions taken while implementing `project.py`, `commands.py` and `export.py`
(stream C) where the plan or the interface contract left room, or where reality
disagreed with the spec. The user was away from keyboard; each row is a call
made to keep moving.

| area | roadblock | decision | rationale |
|---|---|---|---|
| project / manifest | Plan.md §5 shows no way to remember the id high-water mark, so deleting the newest frame and reopening would recycle its id — violating "never reused". | Added a top-level `"next_id"` integer to `project.json`. On open, `next_id = max(persisted, highest_seen + 1)`. | Smallest possible schema addition; forward-compatible (an old reader ignores it, and the `highest_seen + 1` fallback still works if it is absent). |
| project / Frame | The contract's `Frame` has no place for the captured image's pixel size, but `add_frame(jpeg, settings, size)` is handed one. | Appended two optional trailing fields, `width: int = 0, height: int = 0`, persisted only when non-zero; `capture_size` is also back-filled from the first frame if the project was created without one. | Trailing defaulted fields leave every documented constructor call and keyword valid for the other streams, and the size is genuinely useful (crop maths on mixed-size projects). |
| project / Frame | The contract has no way to express "the manifest references a JPEG that is gone". | Added a runtime-only `missing: bool = False` flag, set by `Project.open`, never written to the manifest. | `open()` must not crash on hand-deleted files; the UI needs to grey the frame out, and the entry must survive a resave so an undo/restore of the file still works. |
| project | `index_of()` behaviour for an unknown id is unspecified. | Returns `-1` rather than raising. | The UI calls it while selections and the timeline are momentarily out of step; an exception there would be a crash, `-1` is a testable sentinel. |
| project | `Project.create(..., crop)` — unclear whether `crop` is a `Crop` or an aspect string. | Accepts `Crop | str | None`; a string is turned into a centred `Crop.for_aspect(...)` against `capture_size`. | Lets the New Project dialog pass `"16:9"` straight through without duplicating the centring maths. |
| project | `open()` is given either a folder or a manifest path by different call sites. | Accepts both; normalises to the containing folder. | Removes a whole class of caller-side bugs, costs three lines. |
| project | `Crop.for_aspect` must clamp to even pixels, but evening the *offsets* the same way as the dimensions pushed `x`/`y` to 2 when the correct answer was 0, and could push `x + w` past the sensor edge. | Dimensions floor to even with a minimum of 2; offsets floor to even with a minimum of 0 and are additionally clamped to `sensor - size`. | Even dimensions are an H.264 requirement, even offsets are a yuv420p chroma-siting nicety, but neither may push the rect off the sensor. Covered by a parametrised test over odd sensor sizes. |
| project | `purge_unreferenced()` versus duplicated frames. | Reference counting by resolved path: a file is purged only when *no* manifest entry points at it. | Duplicates deliberately share one immutable JPEG (see below), so a naive "one file per frame" purge would delete pixels still in use. |
| commands | `DuplicateFrames` could copy the JPEG bytes or share the file. | The copy gets a fresh id but the *same* `file`. | The files are immutable by design, so a byte copy buys nothing and costs disk on a 4032×3024 q95 shoot. |
| commands | Where does a duplicate land — after each source, or all after the block? | Each copy is inserted directly after its own source. | Matches how duplicate behaves in every timeline tool; keeps a non-contiguous multi-select intuitive. |
| commands | `DeleteFrames` has no obvious `sel_after`. | Select the nearest surviving frame *after* the deleted block, else the nearest before it, else nothing. | Matches list/file-manager convention, so the user's next keystroke acts somewhere sensible. Undo still restores the exact pre-delete selection, which is the requirement that matters. |
| commands | `ReorderFrames(ids, insert_at)` — is `insert_at` an index into the pre-move or post-removal list? | Pre-move: it is the drop-gap index a drag indicator reports, `0..len(frames)`. The command subtracts the number of moved frames lying before the gap. | The naive "remove then insert at `insert_at`" is the classic off-by-one and drops a forward-moved block one slot too far right. Pinned down by a 9-case parametrised test plus a dedicated regression test. |
| commands | `CaptureFrame` holds a full-resolution JPEG, and the stack is 200 deep. | The bytes are dropped (`self._jpeg = b""`) once written; undo/redo re-inserts the manifest entry pointing at the file already on disk. | Otherwise 200 undo slots could pin ~1 GB of stills in RAM. Safe because the file is never unlinked. |
| commands | `TimelineCommand` is told to "mark the project dirty" but `Project` had no such flag. | Added `Project.dirty`, set before every save and cleared by `save()`. | Cheap, and gives the UI a close-without-saving check if it ever wants one. Saving still happens on every mutation regardless. |
| export | **The specified ffmpeg command does not produce the right frame count.** Measured on ffmpeg 6.1.1: with the final concat entry repeated, the output has 1–2 *extra* frames (e.g. holds `[1,3,1,2]` @4fps → 8 frames/2.00 s instead of 7/1.75 s; `[1,1]` @30fps → 4 frames). Without the repeat, the whole last entry is dropped (5 frames/1.25 s). | Keep the repeated final entry (it is required — without it the last frame vanishes) **and** pin the output with `-frames:v <sum(holds)>`. | The repeat is the only way to keep the last frame; the cap is the only way to stop its bare entry over-running. With both, all eight tested hold/fps combinations come out at exactly `sum(holds)` frames and `sum(holds)/fps` seconds. Everything else in the specified command line is unchanged. |
| export | Which concat list dialect. | `ffconcat version 1.0` header plus `file`/`duration` lines, absolute single-quoted paths, `-safe 0`. | Explicit about the format rather than relying on the demuxer guessing; `'` in a path is escaped `'\''`. |
| export | Progress denominator. | `frame=` from stderr against `sum(holds)`, clamped to 99 until the process exits cleanly, then 100. | ffmpeg's own `frame=` counts output frames, which is exactly `sum(holds)`; clamping avoids a progress bar that hits 100 and then sits there. |
| export | `Exporter.start()` called while a run is in flight. | Refuses and emits `finished(False, "an export is already running")` rather than queueing or racing. | Exactly one `finished` per `start()`, which is what the export dialog needs. |
| export | The contract does not mention a way to wait for the worker. | Added `Exporter.wait(msecs)` and `Exporter.is_running()`. | Needed for deterministic tests and for a clean application shutdown; purely additive. |
| export | A frame's JPEG is missing at export time. | `build_concat_list` raises before ffmpeg starts, naming up to eight frame ids. | Better than ffmpeg failing halfway with an opaque message after minutes of encoding. |
| tests | `desktop/stopmotion` has no `__init__.py` yet (owned by another stream) and the package is not installed into the venv, so `import stopmotion` fails under pytest's default import mode. | Each of my three test files prepends `desktop/` to `sys.path` before importing. | Avoids touching `pyproject.toml` or adding a shared `conftest.py`, both of which other streams own. Harmless if a `conftest.py` doing the same later appears. |
