# Transport stream decisions

Decisions taken without the user present while implementing the transport /
device layer (`protocol.py`, `device.py`, `camera.py`, `connection.py`,
`tools/fake_phone.py`). The contract in `docs/interfaces.md` was followed
exactly; everything below is a gap it did not specify.

| area | roadblock | decision | rationale |
|---|---|---|---|
| protocol | interfaces.md says pure-JSON messages still carry a 2-byte header length, but PING/PONG are specified as "empty" | `encode(msg)` with no header writes `header_len = 0` and no JSON bytes; `decode` maps `header_len == 0` back to `{}` | Keeps the frame layout uniform (every payload starts with the 2-byte field) while PING/PONG really are empty on the wire. Both sides tolerate `{}` as well. |
| protocol | unspecified: what to do with an unknown type byte | Skip the frame, count it in `MessageReader.skipped_unknown`, keep parsing | The frame length is known, so a newer phone build adding a message type cannot desynchronise the desktop. Real framing damage still raises. |
| protocol | unspecified: reader state after a malformed frame | `ProtocolError` poisons the reader; every later `feed()` raises until `reset()` | Once the byte stream is out of sync, guessing where the next frame starts would silently corrupt captures. The connection drops instead. |
| protocol | `decode()` return for a message with an empty trailing blob | Returns `None`, not `b""` | Matches the `bytes \| None` signature; an empty JPEG is not a useful distinction. |
| protocol | oversize handling | The 64 MiB cap is checked before buffering the body, in both `encode()` and `MessageReader` (cap configurable per reader for tests) | A bogus length prefix must not be able to allocate gigabytes. |
| camera | HELLO's exact JSON shape is not pinned down anywhere, and the Android stream is writing the producer in parallel | `from_hello()` is deliberately forgiving: ranges as `{min,max}`, `{lo,hi}` or `[lo,hi]`; sizes as `[w,h]`, `{width,height}` or `"1920x1080"`; `sensor_size` or `sensor`; `focus_calibration` or `focus_distance_calibration`; case-insensitive enums. Missing fields fall back to conservative defaults and it never raises. `to_hello()` documents the canonical shape and is what `fake_phone.py` emits. | A phone that cannot be parsed is worse than one with slightly wrong slider bounds, and it removes a coordination round-trip with the Android stream. |
| camera | SET_CONFIG lock fields not spelled out | Flat `ae_lock` / `af_lock` / `awb_lock` on the wire (matching the dataclass in interfaces.md); `from_json()` additionally accepts a nested `{"locks": {"ae","af","awb"}}` | Flat matches the published contract; accepting the nested form costs three lines and survives an Android-side misreading. |
| camera | "mid-range ISO, prefer the low end" is not a number | ISO 100, additionally capped at the bottom quarter of the device range (`lo + 0.25 * span`), then clamped | On a static rig with continuous light, noise costs more than shutter speed. A device whose floor is ISO 400 gets 400 rather than an impossible 100. |
| camera | default exposure | 16 666 667 ns (1/60 s), clamped into the device range | Standard indoor shutter; avoids banding under 50/60 Hz mains and is short enough not to blur an accidental rig nudge. |
| camera | defaults for locks | AE, AF and AWB locks all **on** | The single most important setting for flicker-free stopmotion. Drift between frames is far more damaging than a slightly wrong absolute value. |
| camera | requested preview size not offered by the device | `clamped()` snaps to the nearest supported size measured on pixel count **in log space** (ratio, not difference), with aspect ratio as a tie-break | Plain nearest-area is biased towards small sizes: a 1000x560 request would land on 640x480 rather than 1280x720. Ratio distance treats "half" and "double" as equally far. |
| camera | AWB mode unavailable | `DAYLIGHT` if supported, else the first mode the device reports | As specified; the first entry is whatever the device considers its primary mode. |
| device | adb may be absent | `find_adb()` tries the explicit path, then `$PATH`, then `~/Android/Sdk/platform-tools/adb` and two other common SDK locations. An explicit path that does not exist falls through to the others rather than failing | This is a personal tool on one machine; finding a working adb matters more than honouring a stale path. A missing adb produces a status message, never an exception. |
| device | the first `adb devices` of a session starts the adb server, which can take seconds | Polling runs on a `QThreadPool` worker (max 1 thread, one poll in flight) and reports back through a queued signal; `setup_forward()` / `launch_app()` stay synchronous but are short and have 15 s timeouts | Blocking the UI thread for the adb server cold start would be a visible freeze at launch. The two synchronous calls are user-triggered and fast. |
| device | `adb shell am start` exits 0 even when the activity is missing | `launch_app()` also treats output containing `Error` as failure | Otherwise the UI would report a successful launch and then sit on a dead socket. |
| device | statuses repeat every 1.5 s poll | `status` is only emitted when the text changes | Keeps the status bar and any log from being flooded. |
| connection | writes must never happen on the UI thread | Outbound frames go into a `queue.SimpleQueue`; a queued `_wake` signal makes the worker drain it in FIFO order on its own event loop | Guarantees ordering and serialisation even if two UI actions fire in the same tick, and keeps `sendall` off the UI thread. |
| connection | a blocking `recv` loop would starve the worker's timers and queued writes | Reads are driven by a `QSocketNotifier` on the socket fd inside the worker's event loop | Lets ping, capture timeouts and outbound writes share one thread with no extra locking. |
| connection | **crash found while testing**: `stop()` dropped the last Python reference to the worker before the thread had finished, so PySide destroyed the C++ object (and its live notifier and timers) from the UI thread — warnings, then a segfault | `stop()` holds a local reference to the worker until `thread.wait()` returns, and only then releases it; `thread.finished -> worker.deleteLater` was removed in favour of that deterministic ownership | This is the "no thread-destroyed-while-running warnings" requirement; the suite now runs with zero Qt warnings on stderr. |
| connection | `QTimer.singleShot` for capture timeouts leaves an armed timer in the thread if the link drops first | Each capture owns a real `QTimer` in `_capture_timers`, cancelled on CAPTURE_RESULT, on ERROR, and in `_teardown()` | Nothing is left armed when the thread exits, and a late result cannot fire a stale timeout. |
| connection | liveness policy not specified | PING every 2 s; any inbound byte counts as life; 6 s of silence is treated as a dead link and reported through `disconnected` | Three missed ping intervals. Short enough to notice a yanked cable within a capture cycle, long enough to survive a full-res still monopolising the socket. |
| connection | reconnect behaviour when `start()` is called again after a drop | On `disconnected` the connection retires its own (now idle) thread on the next event-loop turn, so a later `start()` builds a fresh one | `ui/main_window.py` drives reconnection with a repeating timer that just calls `start()`; without self-retirement that would silently no-op forever. |
| connection | `request_capture()` signature | Kept `-> str` and added an optional `timeout` keyword (default 15 s from the constructor) | Backwards compatible with the published contract. |
| connection | PREVIEW_CTL payload is only described as `{start\|stop}` | Desktop sends `{"action": "start"\|"stop"}`; the fake phone also accepts `state`, `preview`, and booleans | One canonical form on the wire, tolerant parsing on the receiver. |
| fake phone | "stdlib-only" conflicts with having to produce real JPEGs | PySide6's `QImage`/`QPainter` are used purely as an encoder, with `QT_QPA_PLATFORM=offscreen` forced before the import and a `QGuiApplication` constructed but never `exec()`ed | No third-party dependency is added (PySide6 is already required by the desktop app) and the tool stays headless. Qt refuses to touch fonts or image plugins without a QGuiApplication. |
| fake phone | must run standalone from a checkout with nothing installed | The script puts `<repo>/desktop` on `sys.path` itself, so `python tools/fake_phone.py` works from any directory | The venv has no `pip`-installed copy of the package (no setuptools available offline). |
| fake phone | preview content must make onion skin verifiable by eye | Bouncing ball, sweeping bar, big frame counter, slowly drifting background over a fixed "set"; stills advance the ball 8x faster than preview frames | Consecutive captures must be obviously different when composited under an opacity slider; consecutive preview frames must be smooth. |
| fake phone | it clamps SET_CONFIG using the desktop's own `camera.py` | Kept, rather than duplicating clamp logic | It is a dev tool, and it exercises the real clamping code end to end. The real phone will clamp in Kotlin. |
| tests | the package is not importable: the venv has no setuptools, so `pip install -e desktop` fails offline | Each test file prepends `desktop/` to `sys.path`; additionally a `stopmotion-dev.pth` was dropped into the venv's site-packages so `python -m stopmotion` works too | No network, no system pip, and `conftest.py` belongs to no single stream. The `.pth` is environment setup, not a repo file. |
| tests | port 8099 is occupied on this machine by a live `adb forward` | Every test picks a free ephemeral port and passes `--port` to the fake phone | Tests must not fight the real tunnel or each other. |
| tests | `DeviceManager` has no test file of its own in the ownership split | Its tests live in `test_fake_phone.py`, driven by a stub `adb` shell script written into `tmp_path` | That file is already the "works with no hardware attached" file, and a stub adb exercises the whole polling path deterministically. |
